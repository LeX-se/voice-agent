# ТЗ: Локальный голосовой агент «Voice Agent»

## 0. Назначение документа

Это техническое задание на разработку приложения для пользователя **без навыков программирования**.

Исполнитель: coding-агент **Qwen coder**.

Исполнитель должен:
1. Самостоятельно создать все файлы проекта.
2. Реализовать весь указанный функционал.
3. Не требовать от пользователя написания кода, установки Python-библиотек вручную или работы с терминалом.
4. Пользователь должен только запустить `install.bat`, а затем `start.bat`.

Не задавать пользователю уточняющих вопросов по архитектуре: решения уже приняты и описаны ниже.

---

## 1. Цель

Создать локальное консольное приложение для Windows 10 x64, которое:

- слушает микрофон и распознаёт русскую речь офлайн;
- принимает текстовый ввод из консоли;
- ищет информацию в локальных текстовых заметках и документах;
- передаёт вопрос и найденные фрагменты в локальную модель через Ollama;
- получает ответ модели;
- печатает ответ в консоли;
- озвучивает ответ голосом IVONA 2 Maxim;
- записывает каждый обмен репликами в локальную базу диалогов.

Всё должно работать на одном компьютере, без интернета и без облачных сервисов.

## 5. Файлы запуска

### 5.1. `install.bat`

Должен:
1. Переходить в свою папку через `cd /d "%~dp0"`.
2. Проверять наличие Python 3.11 (допустим вызов `py -3.11`, если `python` отсутствует).
3. Создавать `.venv`, если его нет.
4. Активировать окружение.
5. Обновлять `pip`.
6. Устанавливать `requirements.txt`.
7. При ошибке выводить сообщение на русском и не закрывать окно мгновенно.
8. Завершаться выводом `pause`.

### 5.2. `start.bat`

Должен:
1. Переходить в свою папку через `cd /d "%~dp0"`.
2. Активировать `.venv`.
3. Запускать `python app\main.py`.
4. При отсутствии `.venv` выводить: «Сначала запустите install.bat».
5. Включать UTF-8 вывод: `chcp 65001 >nul`.
6. Завершаться выводом `pause`.

Оба файла обязаны корректно работать при пути `C:\projects\Voice agent` (с пробелом).

## 7. Запуск приложения: последовательность

При старте `app/main.py`:

1. Создать отсутствующие папки.
2. Настроить логирование в `logs/app.log`.
3. Инициализировать SQLite.
4. Проверить доступность Ollama через `GET /api/tags`.
5. Проверить наличие модели `qwen2.5:3b`.
6. Проверить наличие Vosk-модели; при наличии загрузить её один раз.
7. Инициализировать синтез речи и выбрать голос.
8. Если папка `knowledge` содержит файлы, а база знаний пуста — автоматически проиндексировать её.
9. Вывести блок статуса и список команд.
10. Если синтез доступен, произнести короткое приветствие.
11. Войти в главный цикл ввода.

**Любой недоступный компонент не должен приводить к падению приложения.** Приложение обязано работать в текстовом режиме без микрофона, без Vosk и без TTS.

## 8. Ввод пользователя

### 8.1. Текстовый ввод

Пользователь печатает вопрос и нажимает Enter. Текст отправляется в поиск и LLM.

### 8.2. Голосовой ввод

Запускается:
- пустой строкой + Enter;
- командой `/voice`.

Требования к `app/stt.py`:
- `sounddevice.RawInputStream`, 16000 Гц, моно, `int16`;
- передавать сырые PCM-буферы в `vosk.KaldiRecognizer`;
- использовать RMS-порог для детекции речи;
- начинать отсчёт тишины только после появления речи;
- останавливаться после `STT_SILENCE_SECONDS` тишины;
- останавливаться по `STT_MAX_SECONDS`;
- при отсутствии речи в течение `STT_WAIT_FOR_SPEECH_SECONDS` сообщать об этом;
- объединять результаты `Result()` и `FinalResult()`;
- вернуть пустую строку, если речь не распознана;
- не отправлять пустую строку в LLM.

Если микрофон недоступен или модель отсутствует — вывести понятное сообщение на русском и вернуться в главное меню.

Аудиофайлы на диск не сохранять.

## 9. База знаний и индексация

### 9.1. Поддерживаемые форматы

На первом этапе: `.txt`, `.md`, `.markdown`, кодировка UTF-8 (с допуском `errors="ignore"`).

Файлы больше 10 МБ пропускать с предупреждением.

### 9.2. Разбиение на фрагменты

- целевая длина фрагмента: 900 символов;
- перекрывание соседних фрагментов: 80 символов;
- по возможности резать по границам абзацев;
- пустые фрагменты не сохранять.

### 9.3. Хранение

Таблица `docs_meta`:

```sql
CREATE TABLE IF NOT EXISTS docs_meta (
    id INTEGER PRIMARY KEY,
    source TEXT NOT NULL,
    mtime INTEGER,
    size INTEGER,
    hash TEXT,
    indexed_at TEXT DEFAULT CURRENT_TIMESTAMP
);
```

Полнотекстовый индекс:

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS docs USING fts5(
    source UNINDEXED,
    chunk,
    doc_id UNINDEXED
);
```

Если FTS5 недоступен — создать обычную таблицу `docs(id, source, chunk, doc_id)` и использовать поиск через `LIKE` с экранированием специальных символов.

Повторная индексация того же файла должна сначала удалять его старые фрагменты. Файлы, чьи `mtime`, `size` и `hash` не изменились, повторно не индексировать.

## 10. Поиск — `app/search.py`

Функция `search_docs(query: str, limit: int = 3) -> list[SearchHit]`:

1. Токенизировать запрос регулялярным выражением `\p{L}+|\p{N}+` (в Python: `re` с `str.isalnum`, либо `[\w]+`), привести к нижнему регистру.
2. Убрать стоп-слова русского языка (`и`, `в`, `на`, `что`, `как`, `про`, `это`, `а`, `the` и т.п.).
3. Для FTS5 собрать запрос вида `"токен1" OR "токен2"`, корректно экранировав кавычки.
4. Вернуть не более 3 фрагментов, отсортированных по релевантности.
5. Обрезать каждый фрагмент до 700 символов.
6. Вернуть вместе с текстом путь к источнику.

Если подходящих фрагментов нет — вернуть пустой список. Это **не** ошибка: вопрос всё равно отправляется в LLM без контекста.

## 11. Работа с Ollama — `app/llm.py`

Эндпоинт: `POST {OLLAMA_BASE_URL}/api/chat`.

Запрос:

```json
{
  "model": "qwen2.5:3b",
  "messages": [],
  "stream": false,
  "options": { "temperature": 0.3 }
}
```

Таймаут: 300 секунд.

Формирование `messages`:
1. `system`: инструкция голосового ассистента.
2. При наличии найденных фрагментов — второе `system` сообщение с контекстом и путями источников.
3. Последние `HISTORY_MESSAGES` сообщений текущей сессии.
4. Текущий `user` запрос.

Системная инструкция:

```text
Ты локальный голосовой ассистент на Windows.
Отвечай по-русски, кратко и ясно, чтобы ответ можно было озвучить.
Если дан контекст из локальной базы знаний, опирайся на него и упоминай источники.
Если информации нет, честно скажи, что не нашел точных данных.
Не выдумывай факты. Не используй markdown-таблицы и блоки кода.
```

Проверки ошибок:
- Ollama недоступна → понятное сообщение, предложить проверить запуск и выполнить `ollama serve`;
- модель отсутствует → предложить `ollama pull qwen2.5:3b`;
- HTTP-ошибка или некорректный JSON → сообщение без stack trace, подробности в `app.log`.

В любом случае главное меню должно остаться работоспособным.

## 12. Озвучка — `app/tts.py`

Использовать `pyttsx3` с драйвером `sapi5`.

Требования:
1. Инициализировать движок **один раз** при старте, в главном потоке.
2. Выбор голоса по подстроке в имени или ID, в порядке приоритета: `Maxim`, `IVONA`, затем любой голос со `Russian`/`ru`.
3. Если подходящий голос не найден — использовать голос по умолчанию и сообщить об этом.
4. Скорость речи: `175`.
5. Перед озвучкой очищать текст:
   - удалять блоки ```` ```...``` ````;
   - удалять символы `* _ # > |` и обратные кавычки;
   - схлопывать пробелы;
   - обрезать до 1200 символов по границе слова.
6. Вызывать `say()` + `runAndWait()`, перехватывать исключения.
7. Полный ответ всегда показывать в консоли; ограничение длины касается только озвучки.
8. При недоступности TTS приложение продолжает работать.

Команда `/voices` должна выводить список всех голосов: имя и ID.

## 14. Команды пользователя

Команды регистронезависимы. Любая строка, начинающаяся с `/`, обрабатывается как команда и **не** отправляется в LLM. Неизвестная команда — сообщение, не падение.

| Команда | Действие |
|---|---|
| `/help` | Список команд и краткая инструкция |
| `/status` | Ollama доступна / модель найдена / Vosk загружен / микрофон / голос TTS / путь к БД / число документов |
| `/voices` | Список доступных голосов |
| `/say <текст>` | Произнести текст через выбранный голос |
| `/voice` | Начать запись с микрофона |
| `/index <папка>` | Проиндексировать поддерживаемые файлы в папке рекурсивно |
| `/file <файл>` | Добавить один файл |
| `/reindex` | Очистить базу знаний и заново проиндексировать `knowledge` |
| `/add <текст>` | Сохранить ручную заметку как источник `manual:<timestamp>` |
| `/history [N]` | Показать последние N реплик из БД (по умолчанию 10) |
| `/exit`, `/quit`, `выход` | Корректно завершить работу |

Все пути в аргументах команд должны поддерживать кавычки, например:
`/index "C:\мои заметки"`

## 15. Главный цикл — `app/main.py`

1. Вывести приглашение: `Нажмите Enter для записи голоса или введите текст/команду:`.
2. Прочитать строку.
3. Если строка пустая → голосовой ввод.
4. Если начинается с `/` → обработать команду.
5. Иначе:
   - выполнить поиск;
   - собрать сообщения;
   - запросить LLM;
   - показать ответ и источники;
   - сохранить диалог;
   - обновить историю;
   - озвучить ответ.
6. Вернуться к пункту 1.

Обрабатывать `KeyboardInterrupt` и `EOFError` как корректный выход.

## 18. Обработка ошибок: обязательное поведение

| Ситуация | Поведение |
|---|---|
| Нет модели Vosk | Сообщение + инструкция, где взять архив `vosk-model-small-ru-0.22.zip`; голосовой ввод отключён, текстовый работает |

| Нет IVONA | Использовать другой голос или отключить озвучку; меню работает |
| Нечитаемый файл при индексации | Пропустить, предупредить, продолжить |
| Ошибка SQLite | Логировать, показать понятное сообщение, не падать |

## 20. Критерии приёмки

Проект принят, если выполнены все пункты:

1. `install.bat` устанавливает окружение без ручных действий пользователя.
2. `start.bat` запускает приложение, в том числе из пути с пробелом.
3. `/status` показывает состояние всех компонентов.

7. Ответ озвучивается при наличии IVONA.

10. `/index knowledge` индексирует файлы без ошибок.
11. Голосовая фраза распознаётся и проходит полный цикл до ответа.
12. Диалоги сохраняются в `data\voice_agent.db`.
13. `/history` показывает сохранённые реплики.
14. `/exit` завершает работу корректно.
15. Приложение не падает при отсутствии микрофона, Vosk-модели или голоса IVONA.
16. Внешних сетевых обращений, кроме localhost, нет.
